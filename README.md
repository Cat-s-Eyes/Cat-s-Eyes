| 대상 | 문제 |
|---|---|

보호자가 겪는 불편과 이 시스템의 해결 방법은 다음과 같습니다.

| 고양이가 언제, 몇 번 밥을 먹었는지 모름 | 밥그릇 구역에 머문 기록으로 밥 먹은 횟수를 셈 | 2, 3 |

| 하루 생활 패턴을 알기 어려움 | 구역에 들어온 시각과 머문 시간을 하루 루틴으로 기록 | 2 |

## 🗓️ 3. 대상 사용자와 사용 시나리오

**대상 사용자:** 출근이나 수업 때문에 낮에 집을 비우는 고양이 보호자. 고양이는 **고양이 화장실(모래)**을 씁니다.

### 하루 사용 시나리오 *(시각·횟수는 예시)*

| 시각 | 상황 | 시스템 동작 |
|---|---|---|
| 출근 전 | 보호자가 웹에서 밥 시간 08:00·18:00, 놀이 예약 14:00, 청소 기준 5회 확인 | 설정을 DB에 저장 |
| 08:00 | 밥 시간 | OLED "밥 시간!" + LED 깜빡임 → 스위치를 짧게 눌러 끄기 |
| 08:02 | 고양이가 밥그릇 구역에 45초 머묾 | 하루 루틴에 기록, **밥 먹은 횟수 +1** |
| 10:15 | 고양이가 화장실 구역에 30초 머묾 | 하루 루틴에 기록, **화장실 간 횟수 +1** |
| 14:00 | 놀이 예약 시각 | 레이저 놀이 자동 시작 → 바닥 범위 안 랜덤 이동 → 5분 뒤 자동 종료 |
| 18:00 | 두 번째 밥 시간 | 08:00과 같은 알림 |
| 저녁 귀가 | 보호자가 웹 접속 | 오늘 횟수와 하루 루틴 확인 |
| 화장실 5회째 | 청소 기준 도달 | OLED "화장실 청소" + LED 깜빡임 → 청소 후 스위치를 짧게 눌러 끄기 → 횟수 0부터 다시 |
| 아무 때나 | 스위치를 길게 누름 | 레이저 놀이 시작. 놀이 중 다시 누르면 즉시 정지 |

> 웹은 파이와 **같은 네트워크(집 Wi-Fi)**에 있을 때 접속합니다. 집 밖에서의 접속은 이번 구현 범위에 넣지 않습니다 ([4-2](#4-2-구현-범위)).

### 4-3. 기능별 세부 내용

#### 🔔 OLED·LED 알림 공통

| 화면 상태 | OLED 표시 | LED |
|---|---|---|
| 평소 | 현재 시각, 오늘 밥 n회 · 화장실 n회 | 꺼짐 |
| 밥 시간 알림 (3번) | "밥 시간!" / "눌러서 확인" | 0.5초 간격 깜빡임 |
| 청소 알림 (4번) | "화장실 청소" / "눌러서 확인" | 0.5초 간격 깜빡임 |
| 레이저 놀이 중 (1번) | "놀이 중" + 남은 시간 | 꺼짐 |

**스위치 하나를 여러 용도로 씀**

| 지금 상태 | 조작 | 동작 |
|---|---|---|
| 알림 중 | 짧게 누름 | 알림 끄기 (청소 알림이면 '청소 완료'로 기록하고 화장실 횟수를 0부터 다시 셈) |
| 레이저 놀이 중 | 누름 | 즉시 정지 |
| 대기 중 | 길게 누름 (1초 이상) | 레이저 놀이 시작 |

- 알림이 떠 있으면 '알림 끄기'를 가장 먼저 처리합니다.
- **구현:**
  - 스위치: gpiozero `Button(17, hold_time=1)`. 6주차와 같은 내부 풀업 방식이고, `when_held`와 `when_released`로 짧게/길게를 구분합니다.
  - LED: gpiozero `LED(27)`의 `blink(0.5, 0.5)`로 깜빡입니다.
  - OLED: `adafruit-circuitpython-ssd1306` + `pillow` (7주차 라이브러리). 한글은 `fonts-nanum` 글꼴을 Pillow로 그려서 표시합니다.

#### 🔴 1. 레이저 놀이

**설정값 *(예시)***
- 놀이 시간 5분
- 이동 속도와 멈춤 시간은 범위 안에서 랜덤
- 놀이 범위는 바닥 네 모서리의 서보 각도로 정함

**작업 순서**

| 순서 | 작업 | 내용 | 완료 기준 |
|---|---|---|---|
| 1 | 단품 테스트 | 서보 0~180° 움직이기, 레이저 켜고 끄기, 스위치 입력 | 부품마다 코드로 동작 |
| 2 | 조립·거치 | 팬틸트 브라켓에 서보 2개와 레이저 고정, 높은 곳에서 바닥을 향하게 설치 | 흔들림 없이 고정 |
| 3 | 바닥 범위 보정 | 놀이 구역 네 모서리에 점을 맞추며 각도 기록, 설정 파일에 저장 | 저장한 범위 밖으로 안 나감 |
| 4 | 랜덤 이동 | 범위 안의 무작위 목표점으로 조금씩 이동, 멈춤 시간과 속도도 랜덤 | 점이 부드럽고 예측하기 어렵게 움직임 |
| 5 | 시작·정지·자동 종료 | 길게 누르면 시작, 놀이 중 누르면 즉시 정지, 정한 시간 뒤 자동 종료 | 세 경우 모두 레이저가 꺼짐 |
| 6 | 예약 시작 | 예약 시각에 자동 시작. 처음엔 설정 파일, 웹 연동 뒤엔 DB 설정값 사용 | 예약 시각에 시작 |
| 7 | 안전 처리·테스트 | 종료·오류·Ctrl+C 때 레이저 끄기, 상하 각도 상한 제한, 반복 테스트 | 7장 시험 통과 |

**동작 상태:** 대기 → 놀이 중 → 대기. 놀이는 시간 종료, 스위치, 오류 중 하나로 끝나고, 끝날 때마다 놀이 기록(시작·종료 시각, 종료 이유)을 DB에 저장합니다.

**떨림 대책:** 서보는 하드웨어 PWM(`dtoverlay=pwm-2chan` + `rpi-hardware-pwm`)으로 움직입니다. 그래도 떨리면 PCA9685 서보 드라이버로 바꿉니다.

**(선택) 웹 조종**

| 작업 | 내용 |
|---|---|
| 조종 API | 시작·정지·방향 이동·상태 조회 |
| 조종 화면 | 상하좌우 버튼, 즉시 정지, 남은 시간 |
| 연결 끊김 처리 | 화면이 1초마다 신호를 보내고, 3초 동안 신호가 없으면 레이저 끄기 |
| 테스트 | 반응 속도, 범위 제한, 연결 끊김 시 꺼짐 |

웹 조종에도 기본 기능과 같은 범위 제한과 시간 제한을 적용합니다.

#### 🤖 2. AI 고양이 감지 및 루틴 기록

**처리 흐름**

```text
USB 카메라 → 사진 1장 → AI 모델로 고양이 찾기 → 고양이 박스의 가운데 점
          → 어느 구역(밥그릇·화장실) 안인지 판정 → 머문 시간 계산
          → 구역을 떠나면 DB에 1줄 기록 (구역, 들어온 시각, 나간 시각, 머문 시간)
```

| 항목 | 방법 |
|---|---|
| 모델 | 이미 학습된 가벼운 모델(YOLOv8n 또는 YOLO11n, COCO의 `cat` 클래스)을 그대로 씀. 새로 학습하지 않음 |
| 속도 | NCNN 형식으로 변환해서 실행. 1~2초에 한 장 처리 *(예시)* |
| 구역 | 웹에서 카메라 사진 위에 사각형으로 지정 (밥그릇 구역, 화장실 구역) |
| 판정 | 고양이 박스의 가운데 점이 사각형 안에 있으면 '구역 안' |
| 끊김 허용 | 인식이 잠깐 끊겨도 3초 *(예시)* 까지는 계속 머문 것으로 봄. 한 번 들른 것을 두 번으로 세지 않기 위함 |
| 확인용 사진 | 최근 사진에 고양이 박스와 구역을 그려 저장. 웹에서 구역 설정과 결과 확인에 사용 |

#### 🍚 3. 식사 알림 & 기록

- **알림:** 웹에서 정한 밥 시간 *(예시: 08:00, 18:00)*이 되면 공통 알림(OLED "밥 시간!" + LED)을 띄웁니다.
- **기록:** 밥그릇 구역에 **N초** *(예시: 20초)* 이상 머문 방문을 **밥 먹은 횟수 1회**로 셉니다.
- N초보다 짧게 지나간 방문도 하루 루틴에는 남지만, 횟수에는 넣지 않습니다.

#### 🚽 4. 배변 알림 & 기록

- **기록:** 화장실 구역에 **N초** *(예시: 20초)* 이상 머문 방문을 **화장실 간 횟수 1회**로 셉니다.
- **청소 알림:** 마지막 청소 뒤로 화장실 간 횟수가 **청소 기준** *(예시: 5회)*에 닿으면 공통 알림(OLED "화장실 청소" + LED)을 띄웁니다.
- **청소 완료:** 알림을 스위치로 끄면 '청소 완료' 시각을 저장하고, 그때부터 횟수를 다시 셉니다. 웹에는 "청소까지 n회"로 보입니다.

## 🔌 5. 하드웨어 및 시스템 구성도

### 5-1. 시스템 구성도

```text
[입력]                [처리: 라즈베리파이 4]                 [저장]           [출력]

USB 카메라  ───────▶  ① 카메라·AI 프로그램  ──── 기록 ───▶  SQLite DB
                       (고양이 인식·구역 판정)               (cat_care.db)
                                                                 ▲  │
스위치      ───────▶  ② 장치 프로그램  ◀──── 설정·횟수 ─────────┘  │
                       (알림·레이저·스위치)                          │
                            │                                        │
                            ├──────▶ OLED · LED  (알림 표시)         │
                            └──────▶ 서보 2개 + 레이저 (놀이)        │
                                                                     ▼
노트북·폰 브라우저  ◀──── HTTP ────▶  ③ 웹 서버 (Flask)  ◀── 읽기·설정 저장
```

- **측정과 웹을 분리:** 프로그램 세 개가 따로 돌고, 같은 SQLite DB로 정보를 주고받습니다 (9주차 웹 IoT 강의 '측정 작업과 웹 요청을 분리').
- **카메라는 ① 프로그램만 엽니다.** 웹에 보이는 사진은 ①이 저장한 최근 사진을 ③이 읽어서 보여 줍니다.

| 구분 | 장치·프로그램 | 역할 |
|---|---|---|
| 입력 | USB 카메라 | 밥그릇·화장실 구역 촬영 |
| 입력 | 택트 스위치 | 알림 끄기, 놀이 시작·정지 |
| 처리 | ① `camera_ai.py` | 고양이 인식, 구역 판정, 방문 기록 |
| 처리 | ② `device.py` | 밥 시간·청소 알림, OLED·LED, 레이저 놀이, 스위치 처리 |
| 처리 | ③ `web.py` | Flask 웹 서버, 조회·설정 API |
| 저장 | `cat_care.db` (SQLite) | 방문 기록, 설정, 구역, 알림, 청소·놀이 기록 |
| 출력 | OLED · LED | 현장 알림 |
| 출력 | 서보 2개 + 레이저 | 바닥에 레이저 점 이동 |
| 출력 | 웹 브라우저 | 하루 루틴·횟수 조회, 설정 |

### 5-3. 핀 배치

| 장치 | BCM 번호 | 물리 핀 | 비고 |
|---|---|---|---|
| OLED VCC / GND | 3.3V / GND | 1 / 9 | |
| OLED SDA | GPIO2 | 3 | I2C 주소 0x3C |
| OLED SCL | GPIO3 | 5 | |
| 스위치 | GPIO17 | 11 | 반대쪽은 GND, 내부 풀업 (6주차와 같음) |
| LED | GPIO27 | 13 | 330Ω 직렬. 6주차에 쓴 GPIO18은 서보용이라 옮김 |
| 좌우(팬) 서보 신호 | GPIO18 | 12 | 하드웨어 PWM0 |
| 상하(틸트) 서보 신호 | GPIO19 | 35 | 하드웨어 PWM1 |
| 레이저 | GPIO23 | 16 | 1kΩ → 2N2222A 베이스 |
| 서보 +5V | 외부 5V 2A | — | 파이 5V 핀에 연결하지 않음 |
| 서보·외부 전원 GND | GND | 6 등 | **파이 GND와 반드시 공통** |
| USB 카메라 | USB 포트 | — | |

**전원과 레이저 연결**

```text
5V 2A 어댑터 → DC 잭 단자대 (+) ──→ 서보 2개 빨간 선
                            (−) ──→ 서보 2개 갈색 선 ──→ 파이 GND (공통)
                   (+)와 (−) 사이: 470~1000µF 커패시터 (선택, 극성 주의)

파이 5V(핀 2) ──→ 레이저 (+)
레이저 (−) ──→ 2N2222A 컬렉터,  이미터 ──→ GND
GPIO23 ──[1kΩ]──→ 2N2222A 베이스
```

- 서보를 파이 5V에 바로 연결하면 움직일 때 전압이 떨어져 파이가 재부팅될 수 있습니다. 그래서 서보 전원은 따로 씁니다.
- 레이저 모듈은 제품마다 핀 배치가 달라서 받은 뒤 확인합니다.
- `dtoverlay=pwm-2chan`을 켜면 3.5mm 아날로그 오디오는 쓸 수 없습니다. 이 프로젝트에서는 오디오를 쓰지 않습니다.

### 6-1. 접속 방법

1. 파이에서 웹 서버를 실행합니다.
   ```python
   app.run(host="0.0.0.0", port=5000)   # 0.0.0.0이어야 다른 기기에서 접속 가능
   ```
2. 같은 네트워크의 노트북이나 폰 브라우저에서 `http://<파이 IP>:5000` 또는 `http://<호스트이름>.local:5000`으로 접속합니다.
3. 학교 Wi-Fi처럼 기기끼리 접속이 막힌 곳에서는 노트북 핫스팟에 파이와 폰을 같이 연결합니다. SSH 포트 포워딩(`ssh -L 5000:localhost:5000 …`)을 쓰면 노트북에서 `http://localhost:5000`으로도 볼 수 있습니다.

### 6-2. 화면 구성

| 화면 | 내용 |
|---|---|
| **메인** | 오늘의 **밥 먹은 횟수**, **화장실 간 횟수**, **화장실 청소까지 n회 (기준 n회)** |
| | **하루 루틴:** 구역에 들어온 시각 · 머문 시간 · 횟수에 들어갔는지 (예: 밥그릇 · 08:02 · 45초 머묾 → 밥 1회) |
| | 지금 알림이 있으면 같이 표시 (예: "화장실 청소 필요") |
| **설정** | 밥 시간 (여러 개), 놀이 예약 시각과 놀이 시간, 청소 기준 횟수, N초 기준 |
| **구역 설정** | 카메라 최근 사진 위에 마우스로 사각형을 그려 밥그릇·화장실 구역 저장 |
| **(선택) 레이저 조종** | 상하좌우 버튼, 시작·즉시 정지, 남은 시간 |

**최신화:** 메인 화면의 JavaScript가 5초 *(예시)*마다 `/api/status`를 자동으로 요청해 숫자와 루틴만 바꿉니다. 새로고침하지 않아도 최신 기록이 보입니다.

```js
setInterval(async () => {
  const s = await (await fetch("/api/status")).json();
  document.querySelector("#meal").textContent = s.meal_count;
}, 5000);
```

### 6-4. 데이터 저장 (SQLite `cat_care.db`)

시각은 9주차 DB 수업처럼 `TEXT`(ISO 형식, 예: `2026-11-20T08:02:10`)로 저장합니다.

| 테이블 | 열 | 내용 |
|---|---|---|
| `visits` | `id`, `zone`, `entered_at`, `left_at`, `duration_s`, `counted` | 구역 방문 1회 = 1줄. `zone`은 `bowl`/`litter`, `counted`는 N초를 넘어 횟수에 들어갔는지 (0/1) |
| `settings` | `key`, `value` | `meal_times`, `play_time`, `play_minutes`, `clean_threshold`, `stay_seconds` |
| `zones` | `name`, `x1`, `y1`, `x2`, `y2` | 밥그릇·화장실 구역 사각형 (사진 크기에 대한 비율 0~1) |
| `alerts` | `id`, `type`, `created_at`, `acked_at` | 알림 기록. `type`은 `meal`/`clean`, `acked_at`은 스위치로 끈 시각 |
| `cleanings` | `id`, `cleaned_at` | 화장실 청소 완료 시각 |
| `play_sessions` | `id`, `started_at`, `ended_at`, `end_reason` | 레이저 놀이 기록. `end_reason`은 `timeout`/`switch`/`error`/`web` |

**계산 방법**
- 오늘 밥 먹은 횟수: `visits`에서 오늘 날짜, `zone='bowl'`, `counted=1`인 줄 수
- 화장실 간 횟수 (청소 뒤): 마지막 `cleanings.cleaned_at` 뒤로 `zone='litter'`, `counted=1`인 줄 수
- 청소까지 남은 횟수: `clean_threshold − 화장실 간 횟수 (청소 뒤)`

**데이터 다루기 규칙**
- 9주차 DB 수업의 방식을 따릅니다: `?` 자리표시자로 넣기, 성공하면 `commit`, 예외가 나면 `rollback`.
- 세 프로그램이 같은 DB 파일을 쓰므로, 쓰는 작업은 짧게 끝내고 바로 커밋합니다.

### 7-1. 시험 방법

| 기능 | 시험 방법 | 통과 기준 |

| | 10분 연속 동작 | 바닥에 테이프로 표시한 범위를 벗어나지 않음 |
| | 예약 시각을 2분 뒤로 설정 | 예약 시각에 시작 |
| | Ctrl+C, 오류 발생 | 프로그램이 끝나도 레이저가 꺼짐 |
| 2. AI 감지 | 고양이 영상·사진 20장 *(예시)*으로 인식 확인 | 고양이를 찾은 비율 기록 (목표 80% 이상 *(예시)*) |
| | 구역 안·밖에 고양이를 둔 영상 | 들어온 시각과 머문 시간이 실제와 몇 초 안으로 맞음 |
| 3. 식사 | 밥 시간을 1분 뒤로 설정 | 그 시각에 알림 |
| | 밥그릇 구역에 N초 이상 / 미만 머문 영상 | 이상이면 1회, 미만이면 0회 |
| 4. 배변 | 청소 기준을 2회로 낮추고 화장실 영상 2번 | 2번째에 청소 알림, 끄면 횟수 0부터 |
| 웹 | 노트북과 폰에서 접속, 설정 바꾸기 | 화면이 5초 안에 최신 기록으로 바뀜, 바꾼 설정이 장치에 반영 |
| 통합 | 세 프로그램을 30분 이상 함께 실행 | 멈춤·재부팅 없이 기록과 알림이 계속 동작 |

| 예상 문제 | 대책 |
|---|---|

| SD카드 손상, 코드 분실 | GitHub에 자주 커밋, DB 파일 주기적 백업 |
